# 重点药品报送对账

监管部门对齐药企、园区和地区上报的重点药品生产供应事实。系统**先做事实对账，
不做药品调拨**：自动找出上下级汇总与委托链的重叠，只给建议值（proposed），
具体采用哪个值由有权监管人员确认（adopted）。

`fixtures/supply_declaration.json` 是一条脱敏的 v2 单主体样例（由 v1 升级，
`record_id`、`occurred_at`、`revision` 语义不变）；`fixtures/scenario_2026_09.json`
是保供会前"三张报表三个总数"的完整对账情景。

## 口径（为什么会有三个总数）

- 药企按**盒**上报，园区/地区按标准单位**支**汇总；换算规则版本化、按时点生效。
- 委托生产被委托方与受托方各计一次：引擎识别重叠，建议按"实物在受托方"去重。
- **名义库存**含全部实物批次；**可用库存**扣除质量隔离等不可发运状态。
- **迟报另成批次**，不并入窗口总数，只单列待人工决定是否追纳。
- 退货回库、质量隔离、更正各自成批次；更正取代旧批次但留痕。

情景中：原始窗口名义 6100 支、委托重叠 1000 支、去重后 **5100（名义）/ 5000（可用）**、
迟报隔离 200 支另列——园区数与去重重算一致，地区数恰好多计一次委托生产。

## 模块

| 文件 | 职责 |
| --- | --- |
| `src/contracts.js` | v1/v2 数据合同读取与 v1→v2 迁移 |
| `src/decimal.js` | BigInt 精确十进制，杜绝浮点误差 |
| `src/units.js` | 版本化换算规则、时点解析、受影响指标声明 |
| `src/inventory.js` | 批次类型/库存状态、名义与可用汇总 |
| `src/snapshot.js` | 不可变快照（内容哈希），层级与时间窗 |
| `src/reconcile.js` | 对账引擎：重叠/换算/隔离/迟报/证据差异，只提建议 |
| `src/decisions.js` | 人工采用台账：仅监管可确认，随月报冻结 |
| `src/intake.js` | 幂等接收回执、迟报/更正批次处理、冻结期拒收 |
| `src/reports.js` | 月报发布冻结、指定快照复算、规则修订定向重算 |
| `src/views.js` | 值班下钻 / 企业 / 园区地区视图，分级可见性 |

## 关键规则

- **幂等回执**：`receipt_id` 由企业幂等键确定性派生，重试返回同一回执；同键不同内容拒绝。
- **月报冻结**：发布后快照与采用值固定，冻结期申报拒收并指引下一期。
- **规则修订**：只重算规则 `affected_metrics` 声明的指标，已发布月报不动，结果作修订建议。
- **可见性**：企业只见自身校验问题、接收状态与采用值；产线明细对其他企业/无关部门不可见，园区与地区只见脱敏后的批次级数字。
- **快照复算**：同一快照 + 同一规则版本必得同一结果（`snapshot_id` 由内容哈希派生）。

## 合同版本与迁移

v2 新增字段（`subject/window/production_roles/batches/evidences`）与枚举
（`batch_type`、`status`）只增不改；新增状态必须同时说明旧数据迁移方式
（见 `migrateV1Record`：保留标识与时间，批次由业务侧补报）。
